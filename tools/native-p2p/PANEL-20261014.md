# P2P connection panel — 2026-10-14

This change redesigns the existing P2P waiting UI. The native connection
controller, retry policy, identity checks, transport, bridge API and server
protocol are unchanged. Baseline: client `791590cd133875ad6a23c2c5380d52a2a296a1e1`.

## Delivered behavior

- A centered 720 logical-pixel panel, capped at 85% of the usable height.
  The header and footer remain fixed while the body scrolls. A stable panel
  height prevents the action buttons moving when a failure reason appears.
- Four named phases, round count, total elapsed time, actual ticket deadline
  and retry countdown. There is no percentage suggesting a chance of success.
- Compact local/peer network cards; expandable Network, Strategy and History
  tabs. Addresses are selectable, observations are numbered, raw errors are
  collapsed and full diagnostic JSON remains available through Copy.
- Mapping stability, prediction evidence and multiple exits are described
  separately. Missing values remain unknown, stable mappings need no prediction,
  TTL 0 means the system default, and socket counts describe use this round.
- UDP authentication, KCP and device identity have separate milestones. A ready
  channel still proceeds through the existing login and permission flow.
- Relay becomes the primary action when waiting for a connection choice.
  Submitting relay disables repeat submission without moving Cancel. Cancel
  remains available until the original connection/view lifecycle takes over;
  a late relay response cannot replace a newer cancellation state.
- The existing 500 ms polling, single request in flight, hidden/background
  suspension and shared terminal close callback are retained. Mapping rows keep
  independent expansion, tab selection and cancellation.

## Review follow-up

Two regressions introduced by the redesign were reproduced and repaired:

1. The custom overlay container used `Focus` where the old alert used a
   `FocusScope`. Tab/Shift+Tab could leave the modal and focus underlying page
   controls. Restoring an automatically managed `FocusScope` keeps traversal
   inside the panel and preserves Escape cancellation. The feature container is
   now named `NativeP2pDialog`, allowing widget tests to exercise the production
   container instead of recreating its margins and shape.
2. Diagnostic events include both `stage` and `choice` records. The history
   view treated every record as a stage, turning Direct/Relay/Cancel decisions
   into misleading "Connecting..." rows. It now displays the actual decision;
   a record containing neither is unknown. The raw diagnostic snapshot remains
   unchanged.

Both targeted tests fail with the respective pre-fix implementation and pass
with the repair. The complete suite now passes 11 tests (8 P2P panel groups and
3 terminal lifecycle tests); static analysis is clean. The responsive screenshot
matrix was rerun using the actual production dialog container. No new bridge,
connection-controller state or translations were needed for these repairs.
